## 4. 확인된 실제 오류 사례

### 고척체육센터

공식 페이지 원문:

```text
자유수영 10시,11시,13시,14시,15시,16시)
```

DB 값: `10:00-10:50`, `11:00-11:50`, `13:00-13:50`, `13:00-14:00`, `14:00-14:50`, `18:00-18:50`

15시와 16시가 빠져 있고, 공식 페이지에 근거가 없는 18시가 들어가 있다.

### 가남체육센터수영장

DB 값은 `06:00-12:00`, `13:00-21:00`으로 6시간·8시간짜리 블록이다. 공식 페이지의 해당 시간대는 `화·목(특강) 11:00~11:50`처럼 강습 시간표이며, 자유수영 시간표가 아니다. 시설 운영시간 또는 강습표를 자유수영으로 잘못 넣은 사례다.

## 6. 한계

- 자동 대조의 `충돌` 판정은 대부분 크롤러가 메뉴 페이지만 받아 시간표 페이지에 도달하지 못한 결과였다. 충돌 자체를 오류로 단정하면 안 된다.
- 상당수 시설이 시간표를 이미지, PDF, JS 렌더링으로 제공한다. 본문 텍스트만으로는 확인되지 않는다.
- 따라서 자동 검수는 우선순위 분류까지만 신뢰하고, 최종 판정은 저장된 증거 원문 확인 또는 전화 확인으로 해야 한다.

## 8. 후속 조치 (같은 날 적용)

### 출처 컬럼 추가

`pools` 테이블에 자유수영 데이터의 근거를 필드 단위로 저장한다.

```text
free_swim_source       근거 URL
free_swim_source_type  official_gov | official_pub | operator_site | aggregator | blog | unknown
free_swim_verified_at  확인 날짜
free_swim_confidence   high | medium | low | needs_check
free_swim_note         비고
```

기존 `docs/data/pool-source-audit.json`과 이번 검수 결과로 625곳을 백필했고, 출처 기록이 없던 174곳은 `unknown` + `needs_check`로 명시했다.

자유수영 데이터 보유 시설의 신뢰도 분포:

| 신뢰도 | 건수 |
|---|---:|
| high | 2 |
| medium | 179 |
| low | 310 |
| needs_check | 307 |

출처 유형으로 보면 공식(지자체·공공기관) 207곳, 애그리게이터·블로그 289곳이다.

### 앱 노출

수영장 상세의 시간표 아래에 근거를 표시한다.

- 확인된 경우: `지자체 공식 페이지 · 2026-09-02 확인`
- 미확인인 경우: `⚠ 수영장 정보 사이트 · 이용 전 시설 문의 필요`
- 근거 페이지 링크 함께 제공

### 증거 저장 보강

`scripts/collect-pool-evidence.mjs`가 정제 텍스트뿐 아니라 원본 HTML과 SHA-256 해시, 수집 시각까지 저장한다.

```text
evidence/pools/{poolId}/{날짜}/
  manifest.json    URL·해시·바이트수·수집시각·수집방식
  page-text.txt    줄 번호가 붙은 정제 텍스트
  html/00.html     원본 HTML
```

`fetchMode`는 현재 `http-fetch-no-js`다. JS로 시간표를 그리는 사이트는 이 방식으로 확인되지 않으므로 브라우저 렌더링 수집이 별도로 필요하다.

## 9. needs_check 재조사 (2026-09-02)

### 방법

`scripts/recheck-free-swim.mjs`로 공식 사이트를 **2단계 깊이**까지 따라가며 자유수영 시간표를 찾고, 원본 HTML과 정제 텍스트를 저장했다. 이후 `scripts/reanalyze-free-swim-evidence.mjs`로 저장된 증거만 재분석했다(네트워크 재요청 없음).

### 대상

needs_check 307곳 중 홈페이지가 있는 267곳. 이 중 231곳 수집 성공, 36곳 접근 실패.

### 결과

| 판정 | 건수 |
|---|---:|

| 일부만 공식 문서에서 확인 | 21 |

### 자동 판정의 오탐을 잡은 사례

1차 자동 판정은 동구문화센터를 `불일치`로 표시했지만, 원문을 직접 읽으니 DB가 공식 시간표와 **요일 단위까지 정확히 일치**했다.

```text
공식: 월수금 8:00~8:50 / 14:00~15:50 / 18:00~18:50
      화목   8:00~8:50 / 14:00~20:50
      토     8:00~8:50 / 14:00~17:50
      일     09:00~12:50 / 14:00~17:50
DB  : 동일
```

원인은 근거 블록을 8줄만 잘라 뒤쪽 요일 행을 놓친 것이었다. 블록 범위를 넓혀 재분석하자 `불일치` 27건 중 12건이 `전부 확인`으로 바뀌었다.

**교훈: 자동 판정의 불일치는 오류가 아니라 확인 실패일 수 있다. 원문 확인 없이 데이터를 고치면 맞는 값을 틀리게 만든다.**
