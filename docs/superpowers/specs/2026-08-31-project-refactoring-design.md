# Openswim 프로젝트 리팩터링 설계

## 목표

현재 사용자 동작과 화면 구성을 유지하면서 프로젝트 전반의 관심사를 분리한다. 데이터 변환과 판정은 순수 함수로, React 상태와 생명주기는 전용 훅으로, 화면 컴포넌트는 표현 계층으로 제한한다. 결과 코드는 더 짧고 읽기 쉬워야 하며, 추상화 자체를 위한 새 계층은 만들지 않는다.

## 동작 보존 원칙

- 검색 결과, 정렬 순서, 필터 의미, 추천 노출 시점은 바꾸지 않는다.
- 화면 문구, 레이아웃, 광고 위치, 탭과 상세 전환 동작은 바꾸지 않는다.
- 위치 권한 요청 시점과 지도 확대 동작을 바꾸지 않는다.
- Neon 우선 조회와 번들 JSON 폴백 정책을 유지한다.
- 동작 변경이 필요한 결함을 발견하면 리팩터링에 섞지 않고 실패 테스트와 별도 변경으로 다룬다.

## 계층과 의존성 규칙

### 순수 도메인 계층

`src/lib`의 도메인 모듈은 입력을 받아 값을 반환하는 순수 함수로 구성한다.

- React 훅과 JSX를 사용하지 않는다.
- DOM, `window`, `document`, localStorage, 지도 SDK, AppsInToss SDK를 직접 참조하지 않는다.
- 검색, 지역 매칭, 일정 판정, 정렬, 거리 계산, 화면 표시용 데이터 가공을 담당한다.
- 날짜처럼 결과에 영향을 주는 외부 상태는 인자로 받는다.
- 각 공개 함수는 실제 사용자 동작을 보호하는 단위 테스트를 갖는다.

### 애플리케이션 훅 계층

화면별 훅은 상태와 부수효과를 조정한다.

- 훅은 JSX를 반환하지 않는다.
- 순수 계산은 `src/lib` 함수에 위임한다.
- 타이머, 위치 API, SDK 이벤트, 스크롤 잠금, 저장소 접근처럼 생명주기가 필요한 작업만 소유한다.
- 반환값은 화면이 바로 렌더링할 상태와 명시적인 이벤트 핸들러로 제한한다.
- 하나의 훅이 여러 독립 생명주기를 소유하면 더 작은 훅으로 나눈다.

### 표현 계층

`src/screens`와 `src/components`는 렌더링과 사용자 이벤트 연결만 담당한다.

- 렌더 도중 대규모 필터링·정렬·인덱스 생성을 하지 않는다.
- SDK나 저장소를 직접 호출하지 않는다.
- 복잡한 중첩 삼항식과 인라인 익명 계산을 이름 있는 값으로 바꾼다.
- 단 한 곳에서만 쓰이고 의미를 더하지 않는 래퍼 컴포넌트와 헬퍼는 만들지 않는다.
- 기존 디자인 시스템과 화면 배치를 유지한다.

### 데이터 접근 계층

Neon 조회, 응답 검증, 번들 폴백을 화면에서 분리한다.

- 원격 호출과 폴백 선택은 데이터 접근 모듈이 소유한다.
- 응답 검증은 별도 순수 함수로 테스트 가능하게 둔다.
- 화면은 로딩·성공·실패 상태만 소비한다.

## 작업 영역

### 기반 도메인

- `src/lib/search.ts`: 정규화, 지역 검색, 수영장 검색과 추천 후보 생성
- `src/lib/pools.ts`: 일정 파싱, 운영 여부, 상태 문구와 필터 판정
- `src/lib/geo.ts`: 좌표 간 거리와 표시 형식
- `src/pool.ts`: 데이터 검증과 원격/번들 로딩 경계

기존 함수가 이미 작고 단일 책임이면 유지한다. 파일 수를 늘리는 것이 목적이 아니며, React 화면에서 재사용하거나 독립 테스트할 가치가 있는 계산만 이동한다.

### 홈

`HomeScreen`에서 다음 관심사를 분리한다.

- 홈 세션 상태와 복원
- 검색 입력과 확정 검색
- 추천 debounce와 추천 선택
- 필터링과 정렬
- 위치 조회 생명주기

화면은 훅이 반환한 값으로 `Top`, 검색창, 필터, 광고, 목록과 빈 상태를 조합한다.

### 지도

`NearbyScreen`에서 다음 관심사를 분리한다.

- 지도 SDK 초기화와 해제
- 검색 상태와 추천
- 중심 좌표와 마커 데이터 생성
- 위치 권한과 현재 위치

지도 SDK 어댑터는 명령형 API를 캡슐화하고, 검색 및 마커 데이터 계산은 순수 함수로 둔다.

### 상세

`PoolDetail`에서 다음 관심사를 분리한다.

- 일정·가격·시설 표시 데이터 가공
- 외부 링크 열기와 지도 링크 생성
- 즐겨찾기와 닫기 이벤트 연결

화면 섹션은 반복되거나 독립적인 렌더링 책임이 있을 때만 컴포넌트로 추출한다.

### 앱 셸

`App`에서 다음 관심사를 분리한다.

- 데이터 로딩 상태
- 탭과 상세 선택 상태
- AppsInToss 뒤로가기 이벤트
- 상세 화면 스크롤 잠금과 복원
- 탭바 숨김 동작
- 이전 Origin 즐겨찾기 이전

전역에 가까운 생명주기는 작은 훅으로 분리하되, 서로 함께 바뀌는 상태를 억지로 여러 훅에 흩뜨리지 않는다.

## 샌드박스 전략

각 작업 영역은 독립 git worktree에서 수행한다.

1. 기반 도메인과 테스트를 먼저 완성한다.
2. 기반 결과를 통합한 뒤 홈과 지도를 서로 독립된 worktree에서 진행한다.
3. 홈과 지도 통합 후 상세와 앱 셸을 각각 진행한다.
4. 각 worktree는 자신이 맡은 파일 외의 구조 변경을 하지 않는다.
5. 공통 인터페이스가 필요하면 기반 단계에서 먼저 정의하고 통합한 뒤 소비 작업을 시작한다.

동일 파일을 여러 worktree가 동시에 수정하지 않도록 작업 DAG를 유지한다. 병렬화는 파일 소유권과 선행 인터페이스가 독립적인 경우에만 사용한다.

## 테스트 전략

- 기존 동작은 characterization test로 먼저 고정한다.
- 발견된 결함과 새 경계 함수는 실패 테스트를 먼저 작성한다.
- 순수 함수는 표 기반 단위 테스트로 정상·빈 값·경계 값을 검증한다.
- 훅은 상태 전환과 타이머/생명주기 정리를 검증한다.
- 화면 테스트는 검색, 추천, 필터, 탭, 상세 열기처럼 사용자에게 보이는 경로만 검증한다.
- 지도·위치·Neon·AppsInToss처럼 외부 환경이 필요한 경계만 대역으로 교체하고, 대역 호출 자체가 아니라 화면 상태와 반환 결과를 검증한다.

각 통합 단계에서 다음 명령을 모두 실행한다.

```bash
pnpm test
pnpm run lint
pnpm exec tsc -b --pretty false
pnpm run build
```

## 완료 기준

- 각 화면에서 순수 계산과 외부 부수효과가 분리되어 있다.
- 화면 컴포넌트가 SDK, 저장소, 대규모 데이터 가공을 직접 수행하지 않는다.
- 새 경계가 코드 길이와 이해 비용을 실제로 줄인다.
- 기존 테스트와 새 회귀 테스트가 모두 통과한다.
- lint, TypeScript, Vite와 AIT 빌드가 통과한다.
- 기능, 문구, 화면 배치와 데이터 의미에 의도하지 않은 변화가 없다.
- 사용되지 않는 코드, 파일, import와 중복 주석이 제거되어 있다.
